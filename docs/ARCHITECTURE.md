# ITP Inventory Frontend — архитектура и правила изменения

Срез: исходники Vue 3 / TypeScript из main на 04.11.2026. Это описание архитектуры, не жестко зафиксированная версия release. Реальные SHA выпуска сверяйте по GitHub и server manifest.

## Контур исполнения

Браузер → HTTPS platform.itpmining.kz/inventory/ → Vue Router + Pinia → same-origin /inventory-api/ → отдельный Laravel 12 / PostgreSQL. Не существует общей auth-сессии, БД и файлового хранилища с Portal или HRM. Браузерное хранение ограничено UI-предпочтениями и выбранной компанией — не сохранять пароль/API-ключ.

В Vite корневой base — /inventory/. Registry загружается eager для быстрого входа, остальные экраны — route-level dynamic import и отдельные чанки с кэшем браузера. Учитывать SPA fallback Apache для прямых ссылок /inventory/stocktakes/{id}, /inventory/facilities/{id}/plan и /inventory/scan/{id}.

## Обязательные инварианты

1. Каждый запрос данных компании содержит идентификатор компании; Laravel заново проверяет membership. Переключение компании должно сбрасывать старые карточки/результаты, отменять незавершенные запросы и перепроверять роль.
2. Viewer не выполняет записи; Manager может операционные изменения, но не управление ролями/архивирование/утверждение списания; Admin имеет административные операции. Сервер контролирует запреты независимо от скрытия UI.
3. Мутации требуют CSRF. Ошибки 401/403/404/409/419/422/429 должны иметь ожидаемое UI-поведение; X-Request-ID передавать поддержке.
4. Любая новая характеристика имущества сначала определяется в справочнике компании и валидируется Backend.
5. Справочники ссылаются на tenant FK; нельзя «исправлять» 404 при чужом ID до 200.
6. Таблицы используют общие BaseDataTable/BasePagination/BaseSelect/BaseMultiSelect/BaseDialog; не писать отдельный HTML select там, где уже есть компонент.
7. Состояния loading/empty/error/readonly должны проверяться на 360/390/768/1024/1440 px, RU/EN/GE, обеих темах.

## Наблюдаемый технический долг

- Исторический Vue 2 каталог остается в корне. Не удалять без отдельного PR и архива/миграционного плана; главное требование — README и CI однозначно указывают на modern/.
- Крупные страницы FacilitiesPage (557 строк), FacilityPlanPage (580), StocktakeDetailPage (507) требуют постепенного дробления по предметным компонентам; не объединять их сразу в одну перепись.
- У Portal есть отдельный UI-пакет; Inventory использует локальные HRM-совместимые примитивы. Версионированная общая библиотека возможна позже, после типизации публичных интерфейсов и smoke-тестов трех приложений.
- На данном этапе нет общей системы SSO, сторонние интеграции по умолчанию отключены.

## Definition of Done для нового функционала

Сценарий и роли документированы; API изменен с тестами в Backend; Vue использует типизированный клиент; добавлены RU/EN/GE, light/dark и mobile; Playwright проверяет happy path и запрет чужой компании; нет новых импортов из legacy; единый PR и план отката.
